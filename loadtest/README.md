# Навантажувальний тест (k6)

Сценарій `script.js` імітує користувачів з профілем «мало записів, багато читань». Кожен віртуальний
користувач (VU) у циклі робить 10 запитів:

1. `POST /tasks` - створює задачу (токен береться один раз у `setup()`, логін не повторюється);
2. 9 читань: `GET /tasks` 4 рази, `GET /tasks/:id` щойно створеної задачі, `GET /tasks/:id` трьох
   випадкових задач з отриманого списку, `GET /authors/admin`.

Між запитами пауза (think time) - випадкова, від 0.5 до 1.5 від `ThinkTime` (за замовчуванням 0.2 с).

Фази: наростання від 0 до N VU за 3 хв, стале навантаження N VU 5 хв, спад до 0 за 2 хв.

Для `GET /tasks` рахується метрика `tasks_list_cache_hit` - частка відповідей із `X-Cache: HIT`.

## Запуск

Потрібні k6 (`winget install GrafanaLabs.k6`), Terraform і AWS CLI з доступом до state і Secrets Manager.

```powershell
.\loadtest\run.ps1 -Vus 300 -RunName run-1-no-cache
```

`run.ps1` бере адресу сервісу з `terraform output app_url`, пароль - із секрету
`cloude-tech-lab1-app-secrets` у Secrets Manager, передає їх у k6 через змінні середовища і нічого з цього
не друкує.

| Параметр | За замовчуванням | Що задає |
| --- | --- | --- |
| `-Vus` | 20 | N - кількість VU на сталому навантаженні |
| `-RunName` | `run-<UTC-час>` | назва прогону і файлів результату |
| `-RampUp`, `-Steady`, `-RampDown` | `3m`, `5m`, `2m` | тривалість фаз |
| `-ThinkTime` | 0.2 | середня пауза між запитами, с |

Локально (застосунок з `compose.yaml`):

```powershell
$env:BASE_URL = "http://localhost:3000"; $env:AUTH_PASSWORD = "change_me"; $env:VUS = "5"
k6 run loadtest/script.js
```

## Результати

- `results/<run>.json` - короткий підсумок: кількість запитів, RPS, частка помилок, p50/p95/p99 загалом і
  по кожному ендпоінту, частка влучань у кеш, UTC-час початку кожної фази. Зберігається в репозиторії.
- `results/<run>.log` - журнал k6 (попередження, помилки запитів), у `.gitignore`.

## Вибір N

N підібрано короткими калібрувальними прогонами (`results/calib-*.json`) на 1 задачі:

| Прогін | N | Запитів за хвилину на сталому навантаженні | CPU задачі | p95 ALB |
| --- | --- | --- | --- | --- |
| calib-1 | 30 | 7 982 | 21% | 2 мс |
| calib-2 | 200 | 50 449 | 99.9% | 46 мс |
| calib-3 | 300 | 50 566 | 87-100% | 180 мс |

Одна задача (0.25 vCPU) обробляє до ~840 запитів/с, далі CPU упирається в 100%. Один VU без черги дає
~4.4 запита/с, тому 300 VU потребують ~1 330 запитів/с - приблизно 1.6 задачі при 100% CPU. На одній задачі
CPU стабільно вище 70%, і для цілі 60% потрібно 3 задачі. Тому для основних прогонів N = 300.
